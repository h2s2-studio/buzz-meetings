# Handoff prompt for the Buzz Meetings team

Continue work on [h2s2-studio/buzz-meetings PR #5](https://github.com/h2s2-studio/buzz-meetings/pull/5), branch `feat/meeting-ux-agents`. Fetch the current PR head. Read [the evaluation](README.md) and run [the agent screen probe](agent-screen.probe.mjs). The evaluated product baseline was `74830bb`. The handoff adds evaluation, screenshots and a runnable transport experiment. Use [Block’s desktop host](https://github.com/block/buzz-app) as the source for plugin behavior and UI, and [Block’s relay](https://github.com/block/buzz) for channel identity, membership and artifacts.

**Build toward this meeting.** Riley is sharing a playtest. Sam says, “Studio, put those three ideas on a whiteboard.” The agent creates a board in that private workspace and presents it as its own selectable screen. Riley adds a card while Sam watches. They ask the agent to turn the selected cards into a document. Sam edits the document while the agent drafts another section. Both items, the decision and the source thread can be reopened after the call. Joining, switching shares, opening an editor, following the presenter and leaving should feel natural to someone who uses Discord or Teams.

**Start from the evidence.** The baseline passed 29 JavaScript tests, 9 Rust tests, 8 Python tests and 40 browser workflows. The separate screen probe passed in Chromium and WebKit with real LiveKit, a real receiving plugin, a scripted presenter and an in-memory editor. Implement actual Buzz agent authoring, durable artifacts, verified presenter identity, in-workspace co-editing and native acceptance. Keep browser/media evidence and native execution evidence explicit in the handoff.

**Suggested parallel ownership**

1. **Meeting reliability.** Fix the eight findings in the evaluation. Start with transcript duplication on resume, tasks carrying into a later call, the disappearing post-leave transcript and capture continuing after a failed agent invitation. Give each fix a regression check through its normal entry point.
2. **Workspace documents and boards.** Give each item its own durable channel-scoped ID, revisions and references. Preserve the existing channel Canvas for standing notes. Expose agent tools for creating and updating document sections and board elements. Support simultaneous edits, conflict recovery and attributed changes. Show a current item and the revision that was presented.
3. **Presentation and UX.** Bind a renderer and presentation-only media identity to the authorized agent and meeting. Render its actual editable item into its screen without capturing the owner’s desktop. Keep human and agent shares independently selectable. Give the agent one roster tile with an artifact title, reliable status, Watch, Edit together and Stop presenting. Support follow, independent exploration, keyboard navigation and a readable board outline.
4. **Integration and acceptance.** Agree on workspace, occurrence, agent, artifact and revision IDs before joining the implementations. Use two native Buzz clients in a private test workspace and a real local agent. Demonstrate a spoken and typed request, simultaneous human sharing, a human edit reaching the remote screen, conflict recovery, access loss, agent removal, reconnect and reopening both items after restart. Record the actual links, results, revisions and any remaining gaps.

Deliver the real document workflow end to end first. Extend the same authoring, persistence and presentation path to the board. Use the current PR as the integration baseline and report exactly what works on the native host.
